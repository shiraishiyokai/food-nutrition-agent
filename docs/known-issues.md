## K7 🟡 部分解决 · 用户差异化数据不持久，刷新即失

- **现象**：个人校准（`userCalibrations`）、配方覆盖（`userRecipeOverrides`）是 `nutrition_db.ts` 的内存 Map；API 补库缓存在 localStorage 但用户校准不在。
- **影响**：用户辛苦校准的「这个菜其实 350 卡」刷新页面就丢；与「永久生效」的 UI 承诺不符。
- **当前状态**：🟡 **校准已修复（2026-09-24）**：`fna.calib.v1` 持久化 + 模块加载恢复 + 备份导入可迁移，浏览器 E2E 验证（校准米饭 50 kcal/100g → reload → 仍生效）。**配方覆盖（upsertRecipeOverride）仍未持久化**——同模式补 localStorage 即可，当前无 UI 入口使用，暂观察。
- **教训**：宣称「永久生效」的承诺必须有对应持久层；持久化 E2E 必须覆盖「写入→刷新→仍在」。

- **影响**：部分菜品数值存在方向性偏差（如煎豆腐命中白豆腐值偏低，实测 #2 已观察）。

## K10 🟡 约束 · 薄荷 API 免费档限制

- **现象**：50 次请求/天（每日重置），拍照识别等高级 API 不开放；429 只报「请明天再试」，无退避重试。
- **影响**：补库吞吐有限；软上限 45 已兜底。多菜同缺时逐个串行调用，预算耗尽后剩余菜静默跳过（返回 null，UI 显示「未命中」）。
- **当前状态**：🟡 设计内约束。勿调高 `SOFT_CAP`；勿绕过负缓存直接打接口。

- **影响**：M1 只能 `npm run dev` 使用；不能把 web 版发给朋友。
